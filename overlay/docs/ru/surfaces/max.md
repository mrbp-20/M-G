# Шлюз MAX

Coddy умеет отвечать в российском мессенджере [MAX](https://max.ru/) (МАКС) как бот. Человек пишет боту в личном чате или упоминает его в группе, и сообщение запускает или продолжает ход агента; ответ потоком приходит в одно сообщение чата. Бот работает внутри `coddy serve` рядом с HTTP-сервером и Telegram-ботом, и каждый диалог - обычная сессия Coddy, поэтому веб-интерфейс показывает его вживую.

Как и [шлюз Pachca](pachca.md), адаптер намеренно меньше [Telegram-шлюза](gateway.md): он читает поток `GET /updates` бота длинным опросом вместо приёма вебхука, поэтому машине с Coddy не нужен публичный адрес. Он поддерживает ходы в чате, несколько команд, кнопки для запросов разрешений субагентов, а также доступ и изоляцию для отдельных чатов.

## Настройка бота в MAX

1. Создайте бота в MAX и скопируйте его токен API. Адаптер передаёт токен как есть в заголовке `Authorization` каждого запроса, ровно как этого ожидает Bot API MAX.
2. Укажите в `ca_file` бандл корневого сертификата Минцифры. MAX отдаёт свой API по сертификату, подписанному российским национальным корнем, которого нет в системном хранилище доверенных сертификатов большинства машин; без `ca_file` клиент падает с ошибкой `x509: certificate signed by unknown authority`. Бандл добавляется к системному хранилищу, а не заменяет его.
3. Впишите свой id пользователя MAX в `admins`, иначе бот никого не впускает, но и никому ничего не одобряет, и `--dry-run` об этом предупреждает.

Токен бота - секрет: оставьте `token` пустым и экспортируйте `MAX_BOT_TOKEN` (например, в `~/.coddy/.env`), чтобы он не попадал в `config.yaml`.

## Конфигурация

```yaml
gateways:
  max:
    enable: true
    token: ""                    # or MAX_BOT_TOKEN in the environment or ~/.coddy/.env
    proxy: ""                    # inherit (default), none, or an http(s)/socks5(h) proxy URL
    ca_file: ""                  # PEM bundle of the MinCifry root (required in practice)
    poll_interval_seconds: 1     # 1 to 60; pause between two polls
    poll_timeout_seconds: 30     # 1 to 60; how long one poll may be held open
    admins: [12345]              # MAX user ids
    default_access: all          # all | admins | group:<name>
    default_isolation: individual  # individual | shared | admin
    user_groups:
      - name: devs
        user_ids: [12345, 67890]
    chats:
      - chat_id: 334
        isolation: shared
        access: group:devs
```

Доступ и изоляция устроены точно так же, как у Telegram ([Уровни доступа](gateway.md#уровни-доступа), [Режимы изоляции сессий](gateway.md#режимы-изоляции-сессий)). `default_access` решает, кто может говорить с ботом, `default_isolation` - будет ли у группового чата своя сессия на каждого человека, одна на всех или одна только для админов, а `chats[]` переопределяет оба ключа для отдельного чата. У личного чата (в MAX это `dialog`) всегда своя сессия.

Те же ключи есть на вкладке **Шлюзы** настроек веб-интерфейса; токен или любой другой ключ, изменённый там, пересоздаёт бота MAX на месте, а Telegram-бот в том же процессе продолжает работать. Справочник полей находится в [config.md](../reference/config.md).

## Запуск

Адаптер собирается с тегом сборки `gateway` (или `gateway.max` только для этого адаптера); бинарники релизов, пакеты и Docker-образ его содержат.

```bash
make build TAGS="gateway.max"
```

```bash
coddy serve --dry-run
```

`--dry-run` проверяет токен через `GET /me`: ошибка для отсутствующего или отозванного токена, предупреждение при пустом списке `admins`. Затем запустите сервер.

```bash
coddy serve
```

Баннер называет бота (`gateway     max`), а в логе появляется `max bot connected` с его именем и id. `CODDY_MAX_API_BASE` направляет бота и пробный запуск на другой адрес API, например на тестовый сервер; по умолчанию это хост Bot API MAX.

## Как ведёт себя бот

- **Личный чат** - каждое сообщение адресовано боту;
- **Групповой чат или канал** - бот отвечает на сообщение любого, кого пускает уровень доступа. Гейтинг по упоминанию (отвечать только на сообщение, в котором бота назвали) пока не реализован, поэтому в группе, куда добавлен бот, стоит держать `default_access` на уровне `admins` или именованной группы;
- **Порядок и наверстывание пропущенного** - каждые `poll_interval_seconds` бот читает `GET /updates` длинным опросом. Курсор сдвигается только после того, как обработана вся страница, поэтому остановка посреди страницы на следующем запуске воспроизводит её, а не теряет необработанный остаток; id сообщения дедуплицируется, поэтому воспроизведённая страница всё равно запускает один ход. Позиция хранится в `<sessions>/gateway_max_cursor`, и после перезапуска бот отвечает на то, что написали, пока он был выключен;
- **Один ход за раз в каждой сессии** - сообщения одного диалога встают в очередь за текущим ходом, а остановка или перезапуск ждут текущий ход и ходы из очереди до 20 секунд, прежде чем бот завершится. Сообщение, которое застало очередь полной (32 ожидающих), не принимается, и в чат приходит просьба отправить его ещё раз;
- **Бот никогда не отвечает сам себе** - его собственные сообщения возвращаются в потоке и отсеиваются по флагу `is_bot` отправителя;
- Соответствие чатов и сессий хранится в `<sessions>/gateway_max_sessions.json`, отдельно от соответствий для Telegram и Pachca.

## Команды

| Команда | Что делает |
|---------|--------------|
| `/help`, `/start` | Список команд и приветствие. |
| `/clear` | Начинает новую сессию для диалога; старая остаётся на диске. |
| `/resume` | Показывает беседы сервера - по восемь на страницу, та, в которой диалог сейчас, отмечена ▶️, - и переключает диалог на выбранную; `/resume <id или часть названия>` находит беседу по префиксу id или по куску названия, а единственное совпадение переключает сразу. Происхождение показано пиктограммой: ✈️ Телеграм, 🌐 веб или консоль, 💬 другой шлюз, без пометки - МАКС; расшифровка есть в `/help`. Беседа загружается до привязки, поэтому нечитаемая оставляет диалог там, где он был. Только админы, как и в Телеграме. |
| `/stop` | Немедленно прекращает ход, который идёт в этом диалоге, — той же отменой сессии, какой пользуются веб-интерфейс и CLI (`session/cancel`: сессия знает, что остановил человек, и ядро завершает ход тихо, вместо того чтобы сообщить об оборванной генерации), — работа модели отменяется, а не просто прячется, — и снимает то, что ждёт за ним в очереди: ожидающее сообщение запустило бы новый ход сразу после возврата остановленного. Отвечается на приёме, до ожидания склейки и до очереди, поэтому никогда не ждёт ответа, который останавливает. В группе — только админам. |
| `/model` | Открывает меню с одной строкой на каждую настроенную модель; текущая модель помечена галочкой ✓. Нажатие переключает модель для разговора и переносит галочку на новый выбор. `/model <id>` по-прежнему устанавливает модель текстом. Меню доступно только администраторам в любом чате, включая личный; нажатие не-администратора отвечает сообщением *Менять настройки в этом чате могут только админы бота.* Выбор администратора также запоминается как последняя модель бота, поэтому следующий новый диалог начнётся с неё; выбор любого другого человека остаётся только в его собственной сессии. |
| `/context` | Заполненность окна контекста сессии этого диалога. |
| `/goal <objective>`, `/goal`, `/goal pause`, `/goal resume`, `/goal clear` | Цель сессии, передаётся сессии, как в любом интерфейсе ([Цель сессии и супервизор](../features/session-supervisor.md)). |
| `/agent`, `/plan`, `/ask`, `/think`, `/nothink`, `/reasoning <level>` | Команды настроек, которые передаются сессии; `--once` и `--count=N` ограничивают их действие следующими сообщениями. |

Любая команда читается в любом регистре: `/stop`, `/STOP` и `/Stop` — одно и то же, как и остальные: слово приводится к нижнему регистру при разборе текста.

Переключение беседы в мессенджере невидимо: сообщения остаются на месте, а сессия за ними становится другой. Поэтому `/resume` сразу после подтверждения кладёт в чат **карточку истории** — разделитель с названием беседы и числом сообщений в ней, затем до тридцати последних сообщений, от свежего к старому, по строке на каждое: метка `DD.MM.YY-hh:mm:ss` по местному времени, затем `👤` у человека или `🤖` у агента, затем текст, обрезанный до 120 знаков, — и кнопку **📜 Развернуть**, которая листает полную стенограмму так же, как кнопка «Подробности» листает вывод инструмента. Стенограмма читается из сессии, а не из чата: МАКС хранит уже разобранный текст, без маркеров markdown. Карточка обязана уложиться в одно сообщение, и длина считается в тех же единицах, что и
предел платформы, — в единицах UTF-16, где значки `👤` и `🤖` стоят по два: счёт в символах давал карточку,
которая проходила нашу проверку и упиралась в платформенную (`Field 'text' size (4014) must be at most 4000`),
и человек после переключения видел подтверждение без истории. Поэтому длинная беседа теряет самые старые
строки и получает примечание «…и ещё N строк», а если платформа отказала уже на самом сообщении, в чат уходит
строка об этом: обещанное не пропадает беззвучно. При переключении ничего не удаляется — в личном диалоге бот может убрать только свои сообщения, и наполовину пустой экран читался бы хуже полного.

Всё, что меняет настройки (команды настроек, `/model` и `/clear`), доступно только админам (`admins`) в любом чате: любому другому бот отвечает *Менять настройки в этом чате могут только админы бота.* Режимы работы и уровень рассуждений остаются доступны всем, где чат не общий; в группе и они админские. Всё остальное, что начинается со слеша, командой не считается: в сообщении человека это обычный текст, и он уходит агенту как написан — так доходит и вопрос, процитировавший строку со слешем (невидимые знаки, которые клиент МАКСа ставит за слешем в цитате, снимаются до разбора, иначе имя команды получалось порченым и сообщение пропадало целиком). Отправителям-ботам бот не отвечает вовсе.

Клиент подсказывает эти команды, когда человек набирает `/`: при каждом старте бот публикует список через `PATCH /me/commands` (не больше 32 команд, имя до 64 символов, описание до 128; пустой список убирает подсказки). Описания — по-русски, потому что МАКС русский продукт и читают их там, а имена команд остаются латиницей: их набирают руками. Публикуется короткий список, который человек встречает первым: `think`, `nothink`, `reasoning` и `toolset` работают и передаются сессии, но в подсказки не попадают, как и псевдонимы `effort` и `no_think`. Отказ публикации — это предупреждение в журнале, а не отказ: бот отвечает и без подсказок, а на следующем старте публикует снова.

## Что можно тем, кто не админ

Бот видит, кто написал каждое сообщение. Его админы (`admins`) могут всё, а остальным доступен разговор и ничего, что меняет агента: только чтение внутри рабочей папки сессии, документация, веб-поиск, план и встречный вопрос; всё остальное, включая инструменты MCP, запрещено, а о каждом вызове, которому нужно одобрение, бот отвечает отказом, каким бы ни был режим разрешений сессии и выданные в ней разрешения, - то же правило действует для Telegram-бота. При пустом списке `admins` все только общаются, а `--dry-run` об этом предупреждает ([Что можно тем, кто не админ](gateway.md#что-можно-тем-кто-не-админ)). Входа в веб-интерфейс у MAX нет, весь интерфейс - сам чат.

## Ответы, лимиты и форматирование

Сообщение, пришедшее пока в беседе идёт предыдущий ход, ждёт своей очереди: ходы одной сессии сериализованы, и сообщение принимается, как только ход закончится. Только когда ожидание исчерпано — около полуминуты, — чату по-русски говорят прислать сообщение ещё раз; внутренний текст «session busy» до человека не доходит.

Шлюз прозрачен в обе стороны. Сообщение, набранное в МАКСе, идёт в беседу, к которой привязан чат, а ход, начатый на другой поверхности — в браузере или в консоли, — публикуется и в этот чат, причём сначала там показывается реплика самого человека: ответ без вопроса, на который он отвечает, читается как монолог. Ход, начатый этим чатом, не дублируется. Вопрос с выбором и запрос разрешения задаются обеим поверхностям сразу: кто ответит первым, тот и решает, а вторая карточка гаснет с пометкой «✅ Ответ дан в другом окне.», чтобы клавиатура, которой уже никто не ответит, не висела без дела.

В карточке вопроса есть и кнопка «✍️ Свой ответ» — то же, что поле свободного ответа в браузере. Нажали — карточка переписывается: кнопки снимаются, внизу появляется «✍️ Свой ответ: напишите его следующим сообщением», и следующее сообщение этого чата становится ответом на вопрос. Одноразово: второе сообщение подряд — уже обычный ход. Команда ответом не считается никогда: она выполняется как команда, а ожидание снимается. Ожидание живёт ровно столько же, сколько вопрос: кончился ход — карточка гаснет с «Больше не жду.». Сообщение без текста, будь то снимок или файл, ответом не становится: карточка повторяет ту же подсказку и ждёт дальше, пока не придёт текст.

Строка и картинка, о которой она, — два сообщения МАКСа с промежутком в секунду-две, и бот держит оба мгновение — три секунды, отсчёт начинается заново с каждым новым сообщением беседы, — чтобы они пошли одним ходом: ответ охватывает текст и картинку вместе, вместо того чтобы сначала ответить на текст, а картинку принять отдельным вопросом. Команда не ждёт никогда: её отвечают сразу, а то, что беседа держала до неё, уходит первым, так что порядок написанного остаётся порядком отвеченного. Ожидание лишь откладывает начало хода; удерживаемое уже прошло курсор опроса, поэтому остановка отдаёт его, а не теряет.

Ответ публикуется одним сообщением с первыми же словами и, пока пишется, правится на месте, а под ним стоит имя работающего инструмента; в конце сообщение заменяется полным ответом. Ответ длиннее 4000 рун делится на следующие сообщения, не разрезая руну. Отправитель держит темп около двух записей в секунду, поэтому ответ приходит порциями, а не отклоняется.

Картинки, которые агент читает по ходу хода, уходят в чат по мере этих вызовов, а не вместе с ответом: каждая — отдельным сообщением с подписью из имени файла.

Всё, что присылает человек, сохраняется, а не пересказывается. Каждое вложение входящего сообщения ложится в собственный каталог беседы `Max-in` внутри её рабочего каталога: документы в `Max-in/Docs`, снимки, записи и видео в `Max-in/Media`. В задании хода каждый сохранённый файл назван с размером, длительностью, полным путём, а если платформа прислала расшифровку записи — и ею. Видео и запись шлюз сам не открывает: что с ними делать, решает агент теми инструментами, что у него есть. Имя сохраняется как прислали, если платформа его дала и система его принимает; разделители, обход каталогов и символы, которые не принимает Windows, исправляются, служебное имя системы отодвигается, а занятое имя получает номер вместо того, чтобы затереть файл. Пределы — платформенные, поэтому файл, который МАКС принял, здесь не отклоняется: 250 МБ на видео, 256 МБ на запись, 4 ГБ на документ, 50 МБ на снимок. Вложение видео несёт страницу проигрывателя, а не файл, поэтому байты берутся из `GET /videos/{token}`, начиная с лучшего разрешения. Длительность не принимается на веру: платформа даёт её в миллисекундах в поле вложения и в микросекундах в ответе о видео, поэтому число пробуется и так, и так, и как секунды, а берётся то чтение, которое сходится с размером самого файла — для видео это от 40 кбит/с до 16 Мбит/с, для записи от 8 до 800 кбит/с. Длительность, которая не сходится ни в одном чтении, не печатается вовсе, вместо «183 мин 20 с» при одиннадцатисекундном ролике. Файл, который не скачался или которого платформа не отдала, называется в чате вместе с причиной, а ход продолжается.

Документ, который агент сделал, доходит так же — отдельным сообщением: вызов, снявший копию файла из рабочего каталога, публикует её в мете вызова, и шлюз отправляет её, как только вызов завершился. МАКС принимает его в три обращения: `POST /uploads?type=file` отвечает адресом, байты уходят туда как multipart в поле `data` без авторизации, а `POST /messages` несёт токен, который вернул второй ответ, — в первом токена нет. Одно сообщение несёт один документ, подпись — имя файла и, если тот, кто его сделал, что-то о нём написал, этот текст следом, с той же обрезкой на 4000 знаков. Уходят девять типов документов — pdf, doc, docx, xls, xlsx, csv, txt, zip, md — до 25 МиБ: это предел Coddy на файл, который вызов инструмента снял как артефакт (100 МиБ на всю сессию); платформа принимает 4 ГБ, но ход длится десять минут, а загрузка внутри него пять, поэтому решает меньший из двух пределов, и отказ называет тот, в который файл не влез. Видео и запись уходят обычными файлами: загрузка и сообщение те же, что у документа, а в чат приходит файл, который можно сохранить. Это сделано намеренно — загрузка видео отвечает не JSON, а разметкой, и токен выдаёт вместе с адресом, тогда как у файла ответ простой и токен ни разу не подводил; платой стал проигрыватель, который чат иначе предложил бы. Виды при этом различаются, потому что такие файлы крупнее и платформа готовит их после загрузки: mp4, m4v, f4v, mov, mkv, webm и avi до 250 МБ, mp3, wav, m4a, ogg, aac, flac и opus до 256 МБ, и ждать приходится дольше — восемь минут на провод, а повтор готовности через пять, десять, пятнадцать и двадцать секунд, не больше пяти попыток. Список отправки повторяет то, что шлюз принимает, поэтому присланный файл всегда можно вернуть: f4v и m4v — тот же контейнер MP4 под другим именем. Всё прочее отклоняется до того, как ушёл хоть байт, по-русски, в чат. Байты — та копия, которую сняла сессия: она сверяется со своим отпечатком, а для чата, который не админский, ещё и с рабочим каталогом самой сессии, поэтому путь, написанный моделью, не открывается никогда. `attachment.not.ready` — платформа ещё обрабатывает загруженное — пережидают, повторяя только сообщение: через три, шесть и девять секунд, не больше четырёх попыток, потому что повторная загрузка оставила бы вторую копию, которую нечем удалить. Картинка заливается в `POST /uploads?type=image` и отправляется как вложение-изображение; берётся та копия, которую сессия сохранила, то есть ровно то, что показали модели, а не файл в рабочем каталоге — он мог измениться. Картинка, которую МАКС не принял, или та, что не читается, просто не отправляется, а ответ всё равно приходит.

Вызов инструмента — отдельное сообщение: команда, которую он выполнил, и кнопка «🔍 Подробности» под ним. Кнопка правит это же сообщение, показывая команду и то, что она вернула; длинный вывод листается страницами, а «Свернуть» возвращает сообщение к одной строке. Вызов называется тем, что он выполнил, а не именем инструмента: агент присылает аргументы вместе с вызовом, поэтому сообщение начинается с команды — одна строка, обрезка на 220 знаках, — а в раскрытом виде команда печатается целиком над выводом, как в вебе. Короткая команда не повторяется: если она уместилась в заголовок, раскрытый вид сразу показывает вывод.

Сам вызов хранит бот, а не сообщение: нажатие после окончания хода всё равно его находит, и в памяти держатся последние 200 вызовов.

МАКС цепляет превью ссылки к любому слову, похожему на имя хоста, а вызов инструмента полон таких: `README.md` — это домен (`readme.md`, к тому же парковка со спамом), а `burst.go` тоже был прочитан как домен, поэтому чат заполнялся карточками на страницы, которых никто не присылал. Поэтому каждое сообщение и каждая правка уходят с параметром запроса `disable_link_preview=true` — это тот самый выключатель, который описан в документации к `POST /messages`, и единственное, что работает: то же имя в теле запроса МАКС молча глотает, а `format` и обратные кавычки не меняют ничего. На `PUT /messages` он тоже действует, хотя в документации к правке его нет — правка без него возвращала карточку. Флаг гасит карточку, но не ссылку: имя файла МАКС всё равно нарисует гиперссылкой — это оператор и поймал 18.10 в карточке истории. Поэтому заслон остаётся вместе с флагом: невидимый пробел после точки в слове-адресе, которого читатель не видит, а МАКС не читает слово как хост. Ссылка, написанная с `http://` или `https://`, сохраняет свои слова и открывается.

Ответ уходит с `format: markdown`, поэтому МАКС рисует то, что написал агент: жирный, курсив, зачёркнутый, код и заголовки приходят оформлением, а не значками. Свои тексты — меню, заметки, подтверждения — идут простым текстом: идентификатор сессии или модели содержит подчёркивания, которые markdown примет за выделение.

## Накопление входящих файлов

Вложения сохраняются в каталоге `Max-in` без общей квоты и автоматической очистки. Следите за свободным
местом на диске, особенно при `default_access: all` и приёмке больших документов или видео. Не
предоставляйте боту непроверенных пользователей без отдельной оценки этого риска. Квота и правила
автоматической очистки находятся в разработке.

Каталог свой у каждой беседы и лежит внутри её рабочего каталога: документы в `Max-in/Docs`, картинки,
видео и записи в `Max-in/Media`. Предел на один файл — только платформенный: МАКС принимает документ до
4 ГБ. Если рабочий каталог под git, папка видна в `git status` — держите её в `.gitignore`.

## Разрешения

Собственному агенту админа разрешается то, что он просит, как в Telegram, потому что оператор настроил бота намеренно; для остальных ничего не одобряется (см. выше). Субагент, определение которого сужает его возможности, спрашивает в чате кнопками **Allow** и **Reject**, а нажатие подтверждается через `AnswerCallback`, чтобы кнопка не повисла. Запрос фонового субагента и ход после пробуждения (фоновая задача, которую агент запустил с `notify_on_finish`) в чат пока не доставляются.

## Что не поддерживается

Приём через вебхук (бот только читает `/updates` длинным опросом), `/mcp`, реакции и формы, ответы и цитирование, гейтинг по упоминанию в группах, запросы разрешений фоновых субагентов, ходы после пробуждения. Правка сообщения человеком ход не запускает. На сообщение без текста и без вложений бот отвечает, что читает текст или картинки; картинки передаются только моделям, у которых в конфигурации задано `multimodal: true`. Распознавание речи — тоже не дело шлюза: расшифровка платформы приводится, если она пришла, а всё остальное остаётся инструментам агента.

## Устранение неполадок

- **`--dry-run` падает с `x509: certificate signed by unknown authority`.** Укажите в `ca_file` бандл корня Минцифры; он добавляется к системному хранилищу, а не заменяет его;
- **Бот отвечает в личном чате, но не в группе.** Проверьте, что `default_access` или переопределение для чата пускает этого человека;
- **Сообщения пропадают после перезапуска.** Курсор хранится в `<sessions>/gateway_max_cursor`; убедитесь, что каталог состояния доступен при следующем запуске;
- **Отладочный вывод только для этого бота** - `logger.levels` с `component: gateway.max` и `level: debug` или `--log-level "info,gateway.max=debug"`. Каждое пропущенное обновление пишется в лог на уровне debug с причиной.
