# Coddy: шлюз MAX

Форк агента [Coddy](https://github.com/coddy-project/coddy-agent) с ботом для российского мессенджера [MAX](https://max.ru/) (МАКС). Каждое сообщение боту запускает или продолжает сессию Coddy, а ответ агента возвращается в тот же чат. Бот работает внутри `coddy serve` рядом с HTTP-сервером, веб-интерфейсом и другими мессенджер-шлюзами.

Это основная ветка `main` — шлюз MAX. Общее описание Coddy, способы установки и список возможностей остаются актуальными для всего, кроме шлюза MAX; см. исходный [README](https://github.com/coddy-project/coddy-agent/blob/main/README.md) и каталог `docs/` этого репозитория.

## Что делает

- Бот читает поток обновлений MAX Bot API через `GET /updates` длинным опросом, поэтому хосту с Coddy **не** нужен публичный IP или вебхук.
- Каждый личный чат, переопределённый групповой чат или общая групповая сессия становится обычной сессией Coddy. Если включён HTTP-сервер, тот же разговор виден в веб-интерфейсе в реальном времени.
- Администраторы (`gateways.max.admins`) могут всё; остальные могут общаться и выполнять только чтение, но не могут запускать инструменты, меняющие файлы, вызывать MCP-инструменты или одобрять запросы разрешений.
- Сообщения дедуплицируются, а курсор опроса сохраняется на диск, поэтому после перезапуска бот не теряет обновления, пришедшие пока он был выключен.
- Строка и присланная сразу после неё картинка приходят двумя сообщениями МАКСа; бот держит их мгновение и ведёт одним ходом, поэтому ответ охватывает обе части.
- Вызов инструмента — отдельное сообщение, названное тем, что он выполнил, когда агент это сообщает: команда запуска, путь чтения; «🔍 Подробности» открывает команду и то, что она вернула, постранично.
- Разговор прозрачен в обе стороны: ход, начатый в веб-интерфейсе, публикуется в чат, к которому привязана беседа, а реплика человека помечается «🌐».

## Получить токен бота и свой id в MAX

1. **Создайте бота в MAX и скопируйте его API-токен.** Точный путь в интерфейсе MAX в этом репозитории не задокументирован; создайте бота через интерфейс MAX для разработчиков и скопируйте выданный токен. Адаптер передаёт токен как есть в заголовке `Authorization` каждого запроса, ровно как этого ожидает MAX Bot API.
2. **Найдите свой id пользователя MAX** и запишите его — он понадобится в списке `admins`. Обычно свой id можно увидеть в профиле или настройках аккаунта MAX; точное расположение смотрите в актуальной документации MAX.
3. **Скачайте бандл корневого сертификата Минцифры** в формате PEM. MAX отдаёт API по сертификату, подписанному российским национальным корнем, которого нет в системном хранилище доверенных сертификатов большинства машин. Без `ca_file` бот не подключится с ошибкой `x509: certificate signed by unknown authority`. Бандл добавляется к системному хранилищу, а не заменяет его.

Токен бота — секрет: оставьте `gateways.max.token` пустым и положите его в `~/.coddy/.env` строкой `MAX_BOT_TOKEN=...`.

## Сборка из исходников

```bash
git clone https://github.com/mrbp-20/M-G
cd M-G
make build TAGS="http,ui,scheduler,memory,cli,gateway,swarm"
```

Тег сборки `gateway` включает адаптер MAX (а также Telegram и Pachca). Бинарник записывается в `build/coddy`.

## Настройка шлюза

Добавьте блок `gateways.max` в `~/.coddy/config.yaml`:

```yaml
gateways:
  max:
    enable: true
    token: ""                    # пусто: читать MAX_BOT_TOKEN из окружения или ~/.coddy/.env
    proxy: ""                    # inherit (по умолчанию), none или URL http(s)/socks5(h)
    ca_file: "/path/to/mincifry-root.pem"   # бандл корня Минцифры в PEM (обязателен на практике)
    poll_interval_seconds: 1     # 1–60; пауза между опросами
    poll_timeout_seconds: 30     # 1–60; сколько один опрос может держать соединение
    admins: [12345]              # ваши id пользователей MAX
    default_access: all          # all | admins | group:<name>
    default_isolation: individual  # individual | shared | admin
    user_groups:
      - name: devs
        user_ids: [12345, 67890]
    chats:
      - chat_id: 334
        isolation: shared
        access: group:devs
```

Справочник полей из `internal/config/config.schema.json`:

| Поле | Значение |
|---|---|
| `enable` | Включить бота MAX в этом процессе `coddy serve`. |
| `token` | Токен бота. Пустое значение читает `MAX_BOT_TOKEN` из окружения или `~/.coddy/.env`. |
| `proxy` | `inherit` (по умолчанию), `none` или URL прокси (`http://`, `https://`, `socks5://`, `socks5h://`). |
| `ca_file` | Бандл дополнительных корневых сертификатов для API MAX, обычно корень Минцифры. |
| `poll_interval_seconds` | Пауза между двумя опросами. |
| `poll_timeout_seconds` | Сколько один опрос может удерживать соединение. |
| `admins` | Id пользователей MAX с расширенными правами. |
| `default_access` | Кто может писать боту: `all`, `admins` или `group:<name>`. |
| `default_isolation` | Изоляция сессий для групповых чатов: `individual`, `shared` или `admin`. |
| `user_groups` | Именованные наборы id пользователей, используемые как `group:<name>`. |
| `chats` | Переопределения для отдельных чатов по id чата MAX. |

У личного чата (в MAX это `dialog`) всегда своя сессия. Доступ и изоляция работают точно так же, как у Telegram-шлюза; подробности см. в `docs/surfaces/gateway.md`.

Те же настройки можно менять на вкладке **Шлюзы** в веб-интерфейсе. Изменение токена или любого другого ключа пересоздаёт бота MAX на месте, не трогая другие поверхности.

## Проверка и запуск

1. Проверьте конфиг и токен:

```bash
./build/coddy serve --dry-run --test-config -config ~/.coddy/config.yaml
```

При работающей настройке появится строка вида:

```
ok       gateways.max: token accepted by MAX, bot <имя бота> (<user_id>)
```

Если `admins` пуст, `--dry-run` предупредит, что некому администрировать бота.

2. Запустите сервер:

```bash
./build/coddy serve
```

В стартовом баннере появится строка `gateway     max`, а в логе:

```
max bot connected ... name=<имя бота> user_id=<id>
```

3. Откройте MAX, напишите боту — он ответит.

## Где развернуть

Подойдёт любой хост с сетевым доступом к MAX Bot API. Публичный адрес **не** требуется: бот сам забирает обновления длинным опросом `GET /updates`. Главное, чтобы каталог состояния Coddy (где лежат `<sessions>/gateway_max_cursor` и `gateway_max_sessions.json`) сохранялся между перезапусками, иначе пропущенные сообщения не будут обработаны повторно.

## Что пока не поддерживается

Приём через вебхук, команда `/mcp`, реакции и формы, ответы и цитирование, гейтинг по упоминанию в группах, запросы разрешений фоновых субагентов, ходы после пробуждения фоновых задач. Правка сообщения человеком не запускает новый ход. На сообщение без текста и без вложения бот отвечает, что читает текст и файлы.

Полное описание поведения см. в `docs/ru/surfaces/max.md`.

## Что ещё в проработке

Групповой режим, режим доступа нескольких клиентов и создание групп находятся **в проработке**. Они работают, но правила раздачи прав на них ещё не устоялись: то, что сегодня закрыто в одном месте, завтра может оказаться открытым в другом — ровно так вышло с меню модели, которое в личном чате оставалось открытым, пока `/resume` уже был закрыт. Поэтому с группами и раздачей прав нужно быть аккуратным: проверяйте на тестовом аккаунте и действуйте на свой страх и риск. Сроков не обещаю: отдельный заход с планом — после первого релиза.

## Накопление входящих файлов

Вложения сохраняются в каталоге `Max-in` без общей квоты и автоматической очистки. Следите за свободным
местом на диске, особенно при `default_access: all` и приёмке больших документов или видео. Не
предоставляйте боту непроверенных пользователей без отдельной оценки этого риска. Квота и правила
автоматической очистки находятся в разработке.

Где именно: каталог `Max-in` свой у каждой беседы и лежит внутри её рабочего каталога — документы в
`Max-in/Docs`, картинки, видео и записи в `Max-in/Media`. Предел на один файл — только платформенный
(МАКС принимает документ до 4 ГБ). Если рабочий каталог под git, папка попадает в `git status` и может
уехать в коммит: держите её в `.gitignore`.

## Устранение неполадок

- **`--dry-run` падает с `x509: certificate signed by unknown authority`.** Укажите в `ca_file` бандл корня Минцифры в формате PEM.
- **`--dry-run` сообщает, что токен отклонён.** Проверьте, что токен актуален; отозванный или опечатанный токен отвечается HTTP 401/403.
- **Бот отвечает в личном чате, но не в группе.** Проверьте `default_access` или переопределение для этой группы.
- **Сообщения пропадают после перезапуска.** Убедитесь, что каталог состояния Coddy находится на постоянном диске и путь к нему совпадает при следующем запуске.
- **Отладочный вывод только для этого бота:** добавьте в `logger.levels` компонент `gateway.max` с уровнем `debug` или запустите с `--log-level "info,gateway.max=debug"`. Каждое пропущенное обновление пишется в лог на уровне debug с причиной.
